# 相互遮挡的行人能否各保留一个框

上轮点名的 10 个重遮挡漏检中，新规则找回了 **5 个**，这 5 个实例对应的邻人也各自保留了独立框。在此前未参与调参的 MOT20 四段录像、12 个取样时刻上，本地检测多命中 **47 个行人**，同时多保留 **24 对**原先未能同时命中的重叠行人，新增 **1 个重复框**。

## 合并规则与旧例复查

原流程会过滤与已有框 IoU ≥0.45 的全身候选。新流程先保留原有输出，再在同一视图中把已有框与实测全身框一对一匹配。尚未认领的全身候选需要有自己的头部，且与不同前帧实测全身框的 IoU ≥0.45。当候选和已有框明显重叠或彼此包含时，两人的头部也必须能在同一视图中分开。只在含至少两个已有框中心的局部放大复核。不同裁剪区域观察到同一人时再次去重。输出新增 `source=crowd_overlap`，并附上头部、前帧、裁剪区域和与相邻框分开的证据。[复核实现](../svsg/recognition/crowd_pairs.py) · [坐标映射与匹配](../svsg/recognition/video_evidence.py) · [回归测试](../tests/test_video_candidates.py)

旧例仍用 MOT17 原视频、模型和一对一评分重放。04 号录像 22 秒找回 ID 95，05 号录像 22 秒找回 ID 30，04 号录像 28 秒找回 ID 91、94、95。合计 140 个标注上，命中 **98 → 104**，误报 **13 → 13**，重复框 **0 → 0**。仍漏的 5 个为 04 号录像的 ID 96、134（各两个时刻）和 28 秒的 ID 126。前四例在本轮复核视图中缺少可另行认领且带独立头部的合格全身框。最后一例与已找回的 ID 95 共享候选，不能凭一个观测给两个人记分。[上轮诊断](pedestrian-occlusion-evaluation-20261120.md) · [逐例证据](../packages/motionspec/bench/results/pedestrian-overlap/cases.jsonl)

## 新录像的配对测试

使用 MOT20-01、02、03、05 四段实拍录像，涵盖室内车站、夜间体育场出口和广场人群。每段取 6、10、14 秒三个末帧及之前 2 秒的画面，以 5 fps 编码。6 秒和 14 秒先测，另外取 10 秒复核最终实现。6 秒与 14 秒的两组分别重放后，16 份归一化候选输入均逐框复现了各自首次运行的结果。两组使用相同视频字节、相同前帧、YOLO11n 和同一个 CrowdHuman ONNX 权重，仅切换重叠复核。MOT20-03 原始宽度为奇数，按编码器要求裁掉最右一列。各组使用同一坐标原点。[MOT20 官方录像说明](https://motchallenge.net/data/MOT20/) · [素材固定版本](https://huggingface.co/datasets/Lekim89/MOT20/tree/5fcaa0ef66906b63195a44672ec260d033545ef4/train)

每个时刻按 IoU ≥0.5 做一对一行人框匹配。若两个有效行人标注之间 IoU ≥0.35，记为一对重叠行人。只有两个标注各匹配到不同预测框，这一对才算同时命中。重复框已经包含在误报里。未匹配且只命中忽略标注的框不计误报。表格按实例或标注对汇总。1,090 个实例来自 472 个序列内不同 ID，同一个人可跨时刻出现。可见比例包含遮挡和边缘截断。[评分实现](../packages/motionspec/bench/pedestrian_eval.py)

| 本地检测 | 原流程 | 加重叠复核 |
|---|---:|---:|
| 命中 / 1,090 | 731 | **778** |
| 漏检 | 359 | **312** |
| 误报（其中重复框） | 56（8） | **57（9）** |
| 重叠双方均命中 / 223 对 | 34 | **58** |
| 可见比例 ≤50% 命中 / 485 | 214 | **254** |
| 可见比例 ≤25% 命中 / 189 | 60 | **79** |
| 小目标命中 / 71 | 16 | **18** |

| 录像 | 命中，原 → 新 | 误报，原 → 新 | 重叠双方均命中，原 → 新 |
|---|---:|---:|---:|
| MOT20-01 | 94 → 98 | 18 → 18 | 6 → 9 |

新流程补了 55 个框，其中 47 个增加命中，7 个落入忽略区，1 个被判为重复框。重复框出现在 05 号录像 6 秒处，新增框 `[250,45,303,194]` 与 ID 316 的真值 IoU 为 0.81，与一个已交付框的 IoU 为 0.52。场景中虽检测到分开的头，两个全身框仍匹配到了同一标注。另取的 10 秒时刻，四段录像合计从 **243 命中、21 误报**变为 **255 命中、21 误报**。本机含解码与结果写盘的候选生成耗时中位数从约 2.38 秒增至 4.26 秒，计时期间还有其他评测并行运行。[逐帧坐标、前帧和分框证据](../packages/motionspec/bench/results/pedestrian-overlap/cases.jsonl)

总召回率从 67.1% 提高到 71.4%。按四个源序列配对有放回重采样，枚举 256 种抽法，总召回差的探索性 95% 百分位区间为 +2.2 至 +5.5 个百分点。仍有 **165/223 对**重叠行人未能同时命中，且 47 个净新增命中有 31 个来自 05 号录像。该实验衡量指定时刻的定位能力。

## 独立模型交付

MiMo V2.6 Flash Token Plan 每次使用单条新用户消息，视频与参数合并输入。两组各 12 次，模型、画面采样率、提示词和生成配置相同。24 次均成功返回可评分答案，响应 ID 各异，接口报告 132,766 tokens。每个请求的输入哈希都从对应视频和参数重新计算并核对。

| 模型最终交付 | 原候选 | 新候选 |
|---|---:|---:|
| 命中 / 1,090 | 725 | **774** |
| 误报（其中重复框） | 54（6） | **55（7）** |
| 重叠双方均命中 / 223 对 | 33 | **58** |
| 可见比例 ≤25% 命中 / 189 | 59 | **78** |

原候选组交付 854 个框，新候选组交付 911 个框，均可在输入候选中逐坐标找到。这里计入了忽略区的框。收益来自上游分开了更多行人，模型在复述坐标时仍有遗漏。[原始回答与逐次评分](../packages/motionspec/bench/results/pedestrian-overlap/model-calls.jsonl)

## 复现

在装有项目、ML 与 crowd 可选依赖的环境中运行。启用 `--crowd-weights` 时应用新的复核规则，可用 `--no-overlap-review` 重放旧规则。以下以 10 秒组为例，6 秒、14 秒组的起始秒分别为 4、12，使用各自独立目录。

```powershell
python packages/motionspec/bench/pedestrian_clips.py out/t10 --dataset MOT20 --start-seconds 8 --sequences 01 02 03 05
python packages/motionspec/bench/pedestrian_detail_eval.py out/t10 yolo11n.pt --sequences 01 02 03 05 --crowd-weights crowdhuman.onnx --compare-overlap
```

第二条命令默认执行本地配对评分。加 `--live` 可使用已配置的 MiMo Token Plan 重放独立会话。[配对评测入口](../packages/motionspec/bench/pedestrian_detail_eval.py)
