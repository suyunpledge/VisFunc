## 误差在哪里

- Qt 留出集有 45 个真值动效。起点 31 个正确、2 个超差、12 个缺测；距离 29 个正确、5 个超差、11 个缺测。可比距离的绝对误差 P90 为 55.6 px。十个水平或垂直单元素平移全部通过，五个并发动效场景中三个全部通过。
- 浏览器留出集有 18 个真值动效。起点和时长各有 12 个正确、6 个缺测。可比样本的起点绝对误差 P50/P90 为 4.34/11.88 ms，时长为 2/12 ms。方向 13 个正确、5 个缺测；距离 12 个正确、1 个超差、5 个缺测。
- 指定的 Qt 尺寸变化 10 项、浏览器尺寸变化 6 项均无可比的尺寸输出。没有一一匹配上的目标，以及匹配后缺失的通道，均计入该项分母。误差分位数仅使用两侧都有数值的记录，不能据此推断整批时序精度。

## 输入、真值与口径

Qt 生成器复用既有场景渲染和同帧属性探针。60 个新变体按种子固定为开发、留出各 30 个，变化因素包括位置、距离、缓动、时长、并发、展开和侧栏重排。过去用过的 6 个基础场景和 9 个较难场景只进入开发集。两个划分共享动效家族，留出验证覆盖同类新参数。全部场景的视频哈希均不同。[固定划分](../bench/splits.json) · [Qt 输入、真值和探针](../bench/corpus/qt.zip)

浏览器在独立 Chrome 页面运行 CSS transition、CSS animation、Web Animations API 和三种真实布局变化，每种每个划分各 2 段。每次采集同时记录 CDP Animation 事件、页面动画时间轴和逐次 rAF 的元素边界及计算样式。起点用 `performance.timeOrigin + Animation.startTime - 首个 screencast 帧的 epoch 毫秒`，持续时间用浏览器动画对象并与 CDP 核对。位移和尺寸取首末几何。两像素见方的绘制标记使静止前后也能收到合成帧。CDP JPEG 按真实帧间隔编码为 H.264，FFprobe 逐帧核对到 1 ms。24 段含 1,914 个帧间隔，范围为 7–375 ms，中位数 9 ms。素材来自 Chrome 无头合成器的本地测试页面；桌面录制器、开放网页和其他浏览器需另验。[浏览器输入、真值和时间戳](../bench/corpus/browser.zip) · [Chrome CDP Page](https://chromedevtools.github.io/devtools-protocol/tot/Page/) · [Chrome CDP Animation](https://chromedevtools.github.io/devtools-protocol/tot/Animation/)

匹配先最大化一对一匹配数，再最大化扫过区域的总 IoU，最低 IoU 为 0.15。匹配不使用位移方向、起点、时长或缓动答案。部件扫过区域重叠时可能发生身份错配。时间字段使用“估计设计时序”。计分容差为起点 34 ms、时长 15% 且至少 17 ms、距离或尺寸 10% 且至少 3 px、适用的透明度端点 0.1。方向按主轴计，2 px 以内计静止，缓动按家族计。每场景另含一个数量项；场景内按适用字段计分，场景间等权。区间用固定种子按场景有放回重抽样 10,000 次。该评分覆盖表中的字段，未单列颜色和回弹幅度，源代码与历史逐项榜的口径有差别。

## 重放

在合并仓库根目录、已安装 MotionSpec 的环境中运行。更换 `--source qt|browser` 和 `--split dev|test` 可复现各组，`--output` 指定 JSON 文件。默认从冻结数据包中只将待测视频交给分析器。

```powershell
python bench/analyzer_eval.py --source browser --split test --output browser-test.json
```

如需独立采集，`bench/capture_browser.py` 接受工作目录、可选 `--chrome` 和 `--output`，需要 Playwright、Chrome、FFmpeg 和 FFprobe。Qt 使用 `bench/capture_qt.py`，需要 PySide6 和 FFmpeg。另选输出文件可保留冻结输入。重新录制浏览器页面会得到新的实际时间戳。
