# 文字识别期间重绘的桌面点击对照

当自绘按钮在 OCR 期间换位，或原按钮旁又出现一个同名按钮时，桌面 Agent 能否在一次调用中做出正确决定？在同一台 Windows 电脑上，对提交 `6d2e8f8` 和本轮工作区版本分别运行 12 次 `click_text`，由 Qt 窗口记录实际收到的点击。

| 窗口在首次截图后的变化 | 预期行为 | 基线 | 本轮 |
| --- | --- | --- | --- |
| 固定布局，一个 High | 点中 High 一次 | 4/4 | 4/4 |
| High 和 Medium 互换位置 | 点中新位置的 High 一次 | 0/4，均未点击 | 4/4 |
| 原 High 不动，另一按钮也显示 High | 返回 `not_started` 且窗口收到零次点击 | 0/4，均点击了原 High | 4/4 |

新版在固定布局每次做一次完整 OCR。两种重绘场景每次做两次，模型端均只需一次动作请求。换位后四次命中的屏幕坐标均为 `(481, 365)`。同名场景四次均在第二次 OCR 读到两个 High。每次测试都另外重发相同请求，24 次重发均返回原回执。此处统计工具动作，模型 token 与端到端会话用时未测量。[逐次结果、屏幕坐标和源码指纹](../packages/motionspec/bench/results/agent-click-recheck-20261126.json)

## 判定和复核范围

两版使用相同的自绘窗口和测试驱动，各做两批，每批重复三个场景两次。批次顺序为新版、基线、基线、新版。每次新建目标窗口、MCP 服务对象及动作回执库。测试先通过真实 OCR 确认初始按钮可见，在首次动作截图交给 OCR 时触发重绘。屏幕采集、文字识别、Windows 点击派发和回执重放都使用项目实际实现。验收同时检查 MCP 返回状态与应用点击记录。测试通过本机 MCP 处理函数直接调用，未接入付费模型。

新版在派发前比对整个识别区域，重新识别最多一次。效果观察和坐标标记使用最后一次核验的画面作为基线。调试时发现系统合成的两像素窗口外框也会自行变化，造成静止按钮被拒绝。现在对与单一窗口边界完全吻合的截图，按 Windows 报告的可见外框宽度裁去外框，识别与复核共用同一范围，再将点击坐标映射回屏幕。无法取得外框信息时使用完整截图。[Windows 窗口外框属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)

这组结果覆盖一次性重排和同名冲突。若识别区域内一直播放视频或动画，两次识别都遇到画面变化时，工具会返回 `not_started`。最后一次采样到系统接收点击之间仍有短暂间隔。

## 复测

在已登录的 Windows 桌面，从仓库根目录运行以下命令。运行测试的 Python 需安装项目的桌面和 OCR 依赖，参数中的解释器需能导入 PySide6。对照旧版时使用相同的测试脚本和窗口程序，让运行脚本的 Python 导入基线检出的 `svsg` 与 `motionspec`。

```powershell
python packages/motionspec/bench/agent_click_recheck.py C:\path\to\qt\python.exe report.json --repeat 4
```
