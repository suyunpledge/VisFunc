# 证据修复与同采样率消融

本轮完成代码证据修复、格式/答案分离和 44 次独立付费调用。结论必须收紧：参数有帮助，但 99% 不是纯函数表达的独立收益；密集采样和已解释好的设计时序都贡献明显。

## 主要结果

所有模型都收到同一批 5fps PNG 帧（每段 6 张），低采样率参数只由这 6 张图重新测量。高采样率参数由同一压缩视频的 40fps 帧测量；两组都不提供 summary，采用相同函数/通道数据结构。

| 口径 | 仅帧图 | 帧图 + 5fps 参数 | 帧图 + 40fps 参数 |
|---|---:|---:|---:|
| 全部预定任务，服务失败计交付零分 | 90/192（46.9%） | 120/192（62.5%） | 166/192（86.5%） |
| 三条件均成功的相同配对集合 | 90/173（52.0%） | 120/173（69.4%） | 150/173（86.7%） |

主实验 36 个任务中，Seed Pro 的 clip_a 基线及 5fps 参数两次 SSL EOF，status=0。原始错误与耗时保留，未自动重试；不能把这两次失败算成语义错误。完整配对分析排除该模型的整个 clip_a 三条件，所以分母统一为 173；包含 11 个模型×片段配对，仍只有 2 个独立场景。

配对结果中，同采样率增加参数提升 30/173（17.3 个百分点）；增加测量密度再提升 30/173（17.3 个百分点）。这是两段素材上的观察差值，不是可外推的因果份额估计。低采样参数仍包含传统视觉测量、拟合与先验；本实验隔离了采样密度，尚未单独隔离函数语法相对其它结构化表示的价值。

| 模型 | 仅帧图 | + 5fps 参数 | + 40fps 参数 |
|---|---:|---:|---:|
| mimo-flash | 9/32（28.1%） | 18/32（56.2%） | 27/32（84.4%） |
| mimo-pro | 19/32（59.4%） | 21/32（65.6%） | 27/32（84.4%） |
| seed-turbo | 10/32（31.2%） | 22/32（68.8%） | 27/32（84.4%） |
| seed-pro | 2/32（6.2%） | 12/32（37.5%） | 27/32（84.4%） |
| gpt-sol | 27/32（84.4%） | 22/32（68.8%） | 31/32（96.9%） |
| gpt-terra | 23/32（71.9%） | 25/32（78.1%） | 27/32（84.4%） |

Seed Pro 的前两列各含一次传输失败，完整可用的 clip_b 三列分别为 2/13、12/13、11/13。

## 无画面：将函数与摘要拆开

| 条件 | MiMo Flash | GPT Sol | 合计 |
|---|---:|---:|---:|
| 只有函数参数 | 27/32（84.4%） | 29/32（90.6%） | 56/64（87.5%） |
| 只有文字摘要 | 32/32（100.0%） | 32/32（100.0%） | 64/64（100.0%） |

这 8 次调用都没有图片或视频。上一轮两次 13/13 同时包含摘要和函数，因此只能证明提取后的文本证据包足以回答这类 UI 测量题，不能归因于纯函数。本轮纯函数仍能承载大量测量信息，但 56/64 低于摘要的 64/64。

差距主要是时间语义：40fps 函数增强组的 26 个错误中，21 个是时长、5 个是起点；纯函数无画面的 8 个错误中，7 个是时长、1 个是起点。例如列表第一行动画设计时长真值 300ms，通道可见变化时长 250ms，命名曲线拟合估计 275ms。MiMo 选择了 250ms；摘要明确呈现设计估计，帮助模型选择符合题意的数值。

下一步协议改进应把 observed_interval 和 estimated_design_timing 明确拆开，由同一个确定性函数生成 JSON 与摘要中的设计估计，并保留拟合误差和来源。这是实验揭示的待优化点，本轮没有在看到结果后改提示词重跑并替换分数。

5fps 参数并不等于 40fps 参数的短版：列表三行的真实上移均为 24px，低采样测得可见位移约为 11.1、3.0、2.0px，并标记 lower_bound。模型若把下界当总位移就会答错。增加提示词无法恢复未观测到的运动。

## 格式、交付与答案

- 44 次请求中 42 次收到有效回答；2 次为传输失败。
- 42 条回答中，严格外壳/schema 通过 30/42；12 条为 MiMo 裸数组。显式包裹后 42/42 可交付。
- 全部任务交付率为 42/44。对成功回答的格式评测与网络可用性分开。
- 42 条可读回答中 35 条至少一个测量字段错误；完整正确为 7/42。字段正确率不能代替整条任务正确率。
- 不改 ease/easing 等字段名，不修数字，不丢弃错误对象。格式不合格时可保留字段诊断，但正式交付指标记失败。

## 代码修复与护栏

1. trace 按实际毫秒间隔切分，跨长空闲的两次动画保持独立，回归验证数量、位移和时长。
2. trace 先验证完整契约，按 fields 声明重排；拒绝空行、错列、重复/越界 tick、非有限数值、非单调时间和无效尺寸。
3. bench 保存每次 attempt，累计嵌套 usage、请求耗时和包含退避的墙钟耗时；未知用量不记零。默认最多 2 次、每次 2000 输出 tokens，402/鉴权错误不重试，不再自动升到 32000。
4. 共用 motionspec.measurement 解包及 schema 校验；报告分别输出严格格式、交付、字段诊断、answer_wrong 和分母。
5. 缓存命中仍核对当前帧 pixel hash/尺寸；相同 raster、不同帧声明在冷/热缓存下均拒绝。
6. 完成的运动候选在内存只保留 top-K；延迟环境判断所需候选写临时文件，64MiB 上限，保留晚出现的干净小运动。
7. 图像函数、识别、尺寸与 YOLO 采用一致 EXIF 坐标；8 种方向均有回归。
8. Qt 静态元素创建/消失单独记录 lifecycle，不伪造成淡入淡出；原生地址复用分配新身份。
9. Forge 多配置匹配显式报歧义，通过 --providers 精确指定槽；记录 slot、endpoint、requested model。
10. 修正中文快速开始上传字段及默认 detector 说明。

验证：全量 287 项通过；最后格式/输入边界调整后，相关 58 项再次通过。Ruff 对新增模块及 SVSG 改动通过。现有第三方 Starlette/AnyIO 弃用警告 1 条。未提交 Git，保留 Claude 先前改动。

## 统计范围与成本

六个模型各主条件都是 32 项（3×6+1 与 2×6+1），合计 192，按项加权。上一轮也是 32/192 口径，12.5%、93.8% 等百分比本身不能反推出更小分母。

独立场景只有两段 UI 动效。不能把 192 个相关字段当独立样本给窄置信区间，本轮不报告通用准确率置信区间。自然视频、小目标、遮挡跟踪扩样尚未执行，也没有把 UI 回归当作上述能力证据。

扩样需独立训练/调试与留出集：自然场景、小目标、遮挡各至少 3 个独立源视频起步，人工双人复核帧级类别、框、可见性与 track ID；分别报告 precision/recall、ID switches、遮挡恢复率。按源视频分层配对 bootstrap 给区间，明确少量片段区间不稳定；同源裁剪不能伪装成新增独立样本。

本轮已返回的 usage 合计输入 378,885 tokens、输出 6,205 tokens；两个失败请求的实际用量未知。MiMo 走 Token Plan，Seed 走按量端点，GPT 走 Responses。没有账单金额，不能声称已证明成本节省。

“小模型追平大模型”目前只能作为待验证的产品假设：MiMo Flash 同帧输入 9/32→18/32→27/32，GPT Sol 为 27/32→22/32→31/32，说明测量工具能缩小部分差距，但低质量参数也可能拉低模型表现。
