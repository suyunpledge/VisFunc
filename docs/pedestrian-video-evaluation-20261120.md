# MOT17 真实视频中的小行人与人物遮挡

在 3 段留出视频的 6 个时刻，MiMo Flash 只看视频时命中 **29/100** 个标注实例，交付了 **162** 个误报框。给模型视频、几何参数和局部检测器的候选框后，命中升至 **57/100**，误报降至 **8**。在这组实验里，额外的定位信息来自检测器。加入候选框的两组各输出 72 个框，全部能在提供给模型的候选中逐坐标找到。

## 输入、真值与独立会话

- 使用 MOT17 训练集的 6 段真实街景序列，02、04、05 用于诊断，09、10、13 留出。每段从源时间 2 秒开始，以 5 fps 取样到 4 秒，生成 MP4。留出视频另取同一序列到 3 秒的前缀，在另一个时刻重复测试。末帧额外保持两帧，问题始终要求定位最后一个画面。几何参数和候选均由交给模型的 MP4 解码得到。留出集的 100 个实例来自 57 个不同的序列内行人 ID，同一人可以在两个时刻被计两次。[数据集论文](https://arxiv.org/abs/2010.07548) · [固定版本的素材与标注](https://huggingface.co/datasets/Lekim89/MOT17/tree/f93908467986c77765667925a526ad07be8ad630/train)
- MiMo V2.6 Flash 使用 Token Plan 接口。45 次请求均返回 HTTP 200，响应 ID 各异，合计 115,805 tokens。每次只发一条新的用户消息，问题、模型、温度和输出上限相同。模型没有收到标注、源序列名称或其他组的回答。每组每个时刻调用一次。材料由输入哈希绑定，可检查每次请求的媒体块数量、原始回答和评分。[逐次记录](../bench/results/20261120-mot17-pedestrians/trials.jsonl)
- **几何参数**含末帧量化颜色区域的框、重心、形状、面积，以及视频运动片段的区域和时间。它是当前系统提供给文本模型的紧凑摘要。**候选框**是额外输入，由本地 COCO 预训练的 YOLO11n 读取画面生成。仅向文本模型传候选时，它收到的是坐标，但整个流程使用了图像检测器。
- 目标取有效且可见度大于零的行人标注，坐标裁到画面。预测与真值按 IoU ≥ 0.5 做一对一匹配，重复框计误报。未匹配框若只命中忽略标注，可排除。小目标定义为框面积小于画面面积的 0.25%，低可见度定义为标注可见比例 ≤ 50%，两组可以重叠。该指标衡量指定时刻的行人检测，低可见度也可能含画面边缘截断。[评分实现](../packages/motionspec/bench/pedestrian_eval.py)

## 留出集结果

按所有预定时刻汇总。一次响应若截断、越界或无法解析，该时刻交付零个框，所有目标计漏检。此时误报数为零只表示程序没有交付框。可无歧义还原的代码围栏、列表外壳等记入逐次记录，评分器不猜坐标。

| 交给 MiMo 的内容 | 有效交付 | 命中 | 误报 | 漏检 | 小目标命中 / 71 | 低可见度命中 / 31 |
|---|---:|---:|---:|---:|---:|---:|
| 只看视频 | 6/6 | 29 | 162 | 71 | 12 | 5 |
| 只读几何参数 | 4/6 | 0 | 0 | 100 | 0 | 0 |
| 视频 + 几何参数 | 3/6 | 7 | 33 | 93 | 2 | 2 |
| 几何参数 + 检测候选，无视频 | 6/6 | 57 | 8 | 43 | 32 | 10 |
| 视频 + 几何参数 + 检测候选 | 6/6 | 57 | 8 | 43 | 32 | 10 |

只取五组都成功交付的 3 个时刻，共 28 个目标，上表五组的命中数依次为 **18、0、7、22、22**，误报数依次为 **27、0、33、3、3**。几何组有效交付中的空列表也参与评分。留出源只有 3 段，模型和数据集都可能接触过公开素材，结果不宜外推到自然视频总体或其他目标类别。

## 具体漏检与误报

- 在 MOT17-13 第 101 帧，只看视频命中 2 个、误报 41 个、漏检 30 个。视频加候选后为 14、1、18。仍漏检 ID 4（46 × 106 像素，可见度约 13%）、ID 36（27 × 93 像素，约 25%）和 ID 51（20 × 60 像素，约 28%）。
- 留出集只看视频的 162 个误报中，112 个与任何有效行人真值的最大 IoU 小于 0.1，另 50 个落在 0.1 到 0.5 之间。加入候选后这两类各剩 4 个。原始回答还能看到等间距排列的框延伸到归一化坐标 1000 以外，有的持续生成直至被截断。
- 3 段留出视频各自两个时刻的「视频加候选」命中数分别为 **11/11、19/29、27/60**。相对只看视频，合计召回率提升 28 个百分点。把同源的两个时刻放在同一块，对 3 个源序列有放回配对重采样，枚举 27 种抽法，召回率差的探索性 95% 百分位区间约为 +10.8 至 +36.7 个百分点。该区间只反映这 3 个来源间的差异。总体还漏了 39/71 个小目标和 21/31 个低可见度目标。这轮没有评估持续跟踪、跨帧身份或遮挡后重新识别。

## 针对性优化和消融

检测器在 1280 像素推理尺度上提出候选。当前帧得分 ≥ 0.40 的框保留，0.25 到 0.40 的框需要与前一取样画面中的同类框一对一匹配，IoU ≥ 0.35。重复像素不能提供额外支持，上一帧中单独出现的框也不会被复制进当前帧。实验使用前一个不同的源取样时刻，间隔约 200 毫秒。本流程导出的是待复核候选，得分代表检测器输出。[候选计算](../svsg/recognition/video_candidates.py)

同一留出集上，直接对检测器的源像素框评分，可以单独观察分辨率和时间复核的影响：

| 检测器设置 | 命中 | 误报 | 漏检 | 小目标命中 | 低可见度命中 |
|---|---:|---:|---:|---:|---:|
| 640，阈值 0.25 | 43 | 11 | 57 | 17 | 7 |
| 1280，阈值 0.25 | 61 | 15 | 39 | 36 | 11 |
| 1280，阈值 0.40 | 53 | 9 | 47 | 28 | 8 |
| 1280，低分框做跨帧复核 | 56 | 10 | 44 | 31 | 10 |

提高分辨率带来了大部分召回收益。与 1280 单帧低阈值相比，跨帧复核减少了 5 个误报，也损失了 5 个真阳性。检测器表使用原始像素框，模型表先把坐标量化到 0..1000，再对实际交付的框评分，所以阈值附近的匹配和分母中的预测数可能略有不同。[检测器逐帧消融](../bench/results/20261120-mot17-pedestrians/detector-ablation.json)

## 复现

从仓库根目录安装 `requirements-dev.txt` 和 `.[ml]`。`motionspec query ... --list` 可列出保留的帧号。对自己的视频显式选择当前帧和相邻的较早帧，传入本地权重即可导出有来源的候选：

```bash
python -m motionspec analyze clip.mp4 -o packet --functions --evidence-every-ms 200
python -m motionspec query packet/functions.json --list
python -m motionspec candidates packet/functions.json --frame 12 --previous-frame 9 --weights yolo11n.pt --label person
```

下面演示复现末帧留出集。`--live` 启动真实模型调用，去掉该参数可用已记录响应重新评分。对调试集使用 `dev`。复现 3 秒时刻时，给准备脚本加 `--midpoint` 并使用独立的输出目录，再对该目录执行同样的留出集步骤。

```bash
python packages/motionspec/bench/pedestrian_clips.py run
python packages/motionspec/bench/pedestrian_eval.py run holdout baseline --live
python packages/motionspec/bench/pedestrian_proposals.py run yolo11n.pt holdout
python packages/motionspec/bench/pedestrian_eval.py run holdout enhanced --live
```
