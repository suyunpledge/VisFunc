# 桌面 Agent 生产加固与部署包实测

上一轮评估认为，桌面 Agent 适合"单台 Windows 电脑、一个本机 Agent 操作指定窗口"，并列出了用于生产前要补的七项。这一轮逐项补上，并用干净检出、离线构建的两种部署包在真实桌面上复测。

## 改了什么

| 问题 | 处理 |
|---|---|
| 断线重试可能重复点击 | 动作先写入防重复回执再执行，同一操作标识重发返回原回执（见 [界面事件与回执](agent-ui-events-20261123.md)）。锁屏、找不到窗口、窗口不在允许规则内，都在写回执之前拒绝，客户端修正后可用原标识重试 |
| 默认没有访问令牌 | `agent-mcp --http` 必须设置 `VISFUNC_MCP_TOKEN`，确需开放时显式加 `--insecure-no-token`。`Start.cmd` 首次启动在 `.env` 生成 43 个字符的随机令牌，不在控制台打印。被拒绝的请求返回 401/403/404 |
| 允许规则只看标题 | 规则可写成 `标题 \| 程序名.exe`，窗口必须属于该程序；`\| 程序名.exe` 放行整个程序；只写标题的规则仍可用，启动时提醒 |
| 同一时间只处理一个请求 | HTTP 服务 4 个工作线程。同一窗口的调用排队，不同窗口并行；截屏流加锁，基准帧按区域记录 |
| 必须登录桌面，锁屏行为未知 | 识别锁屏、UAC/登录安全桌面和会话 0 服务。读屏和操作工具直接报错并说明原因；启动器拒绝以服务方式运行，锁屏启动时提醒 |
| 安装包大 | 新增桌面精简包：只装桌面 Agent 与图片 API 的依赖闭包，不含 torch、ultralytics、PySide6、FFmpeg 和检测模型 |
| 日志只在控制台 | `logs/agent-mcp-calls.jsonl` 每次工具调用一行（时间带时区、工具、窗口、耗时、结果，不含输入文字，5 MB 轮换）；两个服务的输出写入 `logs/api.log`、`logs/agent-mcp.log`（10 MB 换新） |

另外：图片 API 监听非本机地址时必须设置 `SVSG_API_KEY`；动作回执库默认放在包内 `data/`。

## 部署包实测

两个包都从提交 `562b75c` 的干净检出离线构建，解压到新目录后按最终用户的方式使用。

| | 桌面精简包 | 完整包 |
|---|---:|---:|
| ZIP | 156 MB | 917 MB |
| 解压后 | 333 MB | 2.3 GB |
| 依赖 | 38 个 | 72 个 |
| `Start.cmd --check` | 通过 | 通过 |

在桌面精简包上（允许规则 `Keystone agent task | python.exe`）：

| 检查 | 结果 |
|---|---|
| 首次启动 | 生成令牌写入 `.env`，控制台不出现令牌本身 |
| 不带令牌 / 错误令牌 | 均返回 401（修复前客户端只看到连接被重置） |
| 带令牌完成同步任务（改名、开加密、保存、开始同步、确认） | 窗口记录同步到 archive-02、加密、完成、未删除 |
| 不同窗口同时调用 | 另一窗口 4 秒的等待进行中，本窗口读取控件只用 95 ms |
| 规则写成 `\| notepad.exe` 时操作 `python.exe` 的窗口 | 拒绝，错误中写明实际程序；回执库无预留 |
| 操作不存在的窗口 | 直接报找不到窗口，不再附带"派发未确认" |
| 调用日志 | 每次调用一行，时间带时区，输入的文字未出现在日志中 |

实测发现并修复了两个问题：被拒绝的请求未读请求体就关闭连接，Windows 因此发送 RST，客户端只看到连接被重置；权限检查发生在预留回执之后，被拒绝的操作会让同一标识的重试得到"状态未知"。

测试：OCR 环境 521 个通过；未装 OCR 的系统 Python 520 个通过、1 个跳过。

## 仍然存在的限制

- 运行前提仍是已登录、未锁屏的 Windows 用户会话；锁屏期间工具会拒绝工作，不会自动等待解锁。
- 本机 ESET 的浏览器屏幕保护会挡住浏览器截图，浏览器里只能依靠 UI Automation。
- 只写标题的允许规则仍然可用（向后兼容），生产上应改成带程序名的写法。
- 多个 Agent 操作同一个窗口时仍会排队，这是有意的，避免互相干扰。
